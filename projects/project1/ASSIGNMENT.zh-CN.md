# Project 1 作业：CUDA Mandelbrot 渲染器

[English](ASSIGNMENT.md) | [简体中文](ASSIGNMENT.zh-CN.md)

## 1. 概述

补全 `project1` 的起始实现，完成一个 CUDA Mandelbrot 集渲染器。程序必须支持起始项目已经提供的两种模式：

- **在线模式：** 在 OpenGL 窗口中持续渲染。
- **离线模式：** 使用 CUDA 渲染一张图像，并将其保存为 RGBA PNG。

起始仓库有意留空了若干实现位置。你的任务是在保留现有程序结构和命令行接口的前提下补全这些位置。

在线与离线路径必须使用同一个 CUDA 渲染入口和同一个像素生成内核。在线渲染通过已向 CUDA 注册的 OpenGL 着色器存储缓冲对象（SSBO）交换像素。

## 2. 学习目标

本作业旨在练习：

- 将二维图像映射到 CUDA 线程块和网格；
- 在 GPU 上实现复数迭代；
- 实现平滑逃逸时间着色和超采样抗锯齿；
- 将可平凡复制的参数块从 C++ 传入 CUDA；
- 通过 CUDA/OpenGL 互操作协调 CUDA 与 OpenGL SSBO；
- 在 CPU 上维护高精度相机状态，同时向 GPU 提供合适的双精度数值；
- 组织同一套渲染器，使其同时适用于交互程序和离线程序。

## 3. 起始代码与允许的修改

`projects/project1` 下的文件是本作业的修改范围。可以在该目录下添加私有辅助函数或新文件；实现可选的扰动法/参考数据加分项时，也可以扩展渲染函数签名。现有命令行选项的对外行为和构建目标必须保持不变。

共享的 `base/` 目录属于支持代码，本作业不应修改它。

## 4. 必做内容

### 4.1 补全渲染参数块

补全 `render_paramters.h`，包含主机端和设备端渲染所需的全部数值。参数块必须能够描述：

- 图像宽度和高度；
- 最大迭代次数和像素尺度；
- 1×1 或 2×2 采样模式；
- 调色板参数；
- 直接渲染使用的中心坐标；
- 可选加分项使用的额外相机偏移、参考轨道或级数近似数据。

参数块会按值传入设备代码，因此必须保持可平凡复制，不得包含具有资源所有权的指针或带有非平凡状态的 C++ 库对象，并且在主机端和设备端具有一致的含义。

### 4.2 实现 CUDA Mandelbrot 采样

补全 `src/mandelbrot.cu` 中缺失的采样代码。

对于每个样本，使用图像中心、图像尺寸、像素尺度和现有的子像素偏移，将像素坐标映射到复平面。Mandelbrot 递推式为：

$$
z_0 = 0, \qquad z_{n+1} = z_n^2 + c
$$

使用给定的逃逸半径判据（$|z|^2 > 256$），并在达到配置的最大迭代次数后停止。已逃逸样本必须使用提供的平滑迭代辅助函数；未逃逸样本必须表示为内部样本，并由现有着色路径绘制为黑色。

内核必须支持起始代码已经提供的两种采样模式：

- **1×1：** 在像素中心采样一次；
- **2×2：** 在现有的四分之一像素偏移位置采样四次，取平均后再写入输出。

每个像素写入一个 `float4`，RGB 由 `Palette::sample()` 生成，alpha 值为 `1.0`。

### 4.3 实现并启动 CUDA 内核

补全主机端的 `renderMandelbrotSet` 函数。

要求：

- 启动覆盖完整图像的二维网格；
- 在内核中进行边界检查，使图像尺寸不是线程块尺寸整数倍时也能安全处理。

如果实现可选的扰动法或级数近似加分项，应将相关数据传入内核，不得经由 CPU 复制整张图像。

除非外围的资源所有权约定要求同步，否则渲染器相对于调用方必须保持异步执行。

### 4.4 补全离线渲染器

完成 `src/mandelbrot_offline_render.cpp` 中的 TODO。

根据 `OfflineRenderConfig` 构造有效的 `RenderParameters` 对象，包括指定的中心坐标、缩放值、图像尺寸、抗锯齿模式、像素尺度和调色板。调用与在线模式相同的 `renderMandelbrotSet` 入口。保留现有的设备到主机拷贝、图像垂直翻转和 PNG 写入行为。

以下命令必须能够在不创建 OpenGL 上下文的情况下运行：

```text
./project1 --offline
./project1 --offline --width 640 --height 360 --aa 1 --zoom 1 --output result.png
```

### 4.5 补全在线计算路径

补全 `MandelbrotCompute` 及其实现中缺失的部分。

在线渲染器在 CPU 上使用 `HighPrecisionComplex` 和 `HighPrecisionFloat` 存储相机坐标。利用这些状态计算每一帧的相机位置和像素尺度。不得在进行相机计算之前，将整段相机动画的数据降为普通 `double` 数值。

实现还必须：

- 正确响应帧缓冲区尺寸变化事件；
- 填写当前帧的 `RenderParameters`，并调用共用的 CUDA 渲染器；
- 为现有窗口标题返回有意义的帧信息。

#### 可选加分项：扰动法与参考数据

在普通缩放倍率下，必做的直接迭代路径已经足够。若要获得加分，可以针对默认动画中的深度缩放，实现扰动法或其他数值稳定的方法。加分实现可以维护参考轨道，并使用扰动递推，避免将完整的高精度中心坐标转换为经过舍入的 `double` 数值。

起始接口提供的级数近似加速同样属于可选内容。如果实现了这部分，应在使用前校验其指针、阶数、数量、基准（base）、半径和迭代区间；近似不可用或超出有效范围时，必须安全回退。

### 4.6 保留 CUDA/OpenGL SSBO 互操作

在线查看器映射颜色 SSBO，取得 CUDA 指针，将渲染结果写入该指针，解除资源映射，然后在 OpenGL 中绘制 SSBO。必须保留这一所有权交接顺序，尤其需要遵守：

- CUDA 持有资源期间，OpenGL 不得访问已映射的 SSBO；
- 解除映射后，不得再访问对应的 CUDA 指针；
- 帧缓冲区尺寸变化时，重新创建并注册缓冲区；
- 不得替换为基于纹理的 CUDA 互操作实现。

## 5. 功能要求

正确的提交必须满足以下全部要求：

1. 项目可以使用仓库文档中的 CMake 预设构建。
2. 通过 `PROJECT1_OFFLINE_ONLY=ON` 可以完成仅离线构建，且不需要 OpenGL、GLFW 或 GLM。
3. 在线模式打开窗口，并持续更新 Mandelbrot 图像。
4. 离线模式按照指定的分辨率和输出路径写入有效 PNG。
5. 修改中心坐标、缩放值、分辨率和抗锯齿设置时，渲染结果按预期变化。
6. 内部点显示为黑色，已逃逸点使用平滑的调色板颜色。
7. 实现不得引入遍历所有输出像素的 CPU 循环。

## 6. 建议

先使用离线模式，使实验结果便于复现。渲染一张 `640x360` 图像，并手动逐步提高缩放倍率，例如：

```text
./project1 --offline --width 640 --height 360 --aa 0 --zoom 1000
./project1 --offline --width 640 --height 360 --aa 0 --zoom 10000
./project1 --offline --width 640 --height 360 --aa 0 --zoom 100000
```

继续提高缩放倍率，观察普通双精度迭代从何时开始丢失细节或产生不稳定图像。离线渲染器正确运行后，启动窗口程序，观察相机持续向默认目标中心和缩放值推进的过程。比较交互结果与离线图像，排查可见的精度损失、不连续或着色错误。这些实验也适合用来评估可选的扰动法和级数近似加分项。
